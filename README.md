# ai-pingpong

3D 탁구 게임에서 두 **로봇팔**이 **강화학습(Q-러닝)** 으로 탁구를 배웁니다.
`ai-pingpong-rl.html`을 브라우저로 열면 바로 실행됩니다(Three.js를 CDN에서 불러오므로 인터넷 연결 필요).

로봇팔은 공이 어디로 갈지 계산해 주는 기능이 없습니다. 받은 관측(공과 자기 팔의 상태)만 보고 **x(앞뒤)·y(위아래)·z(좌우)** 세 축의 속도와 **손목 각도 2축**(라켓 면 위아래·좌우)을 스스로 골라 움직이고, 보상으로 배웁니다.

## 로봇이 받는 정보와 행동

3 물리 스텝마다 결정합니다. 센서 지연이 있어서 **4스텝 전의 공**을 보고 판단합니다.
학습에는 아래 값을 구간으로 나눈 번호만 쓰입니다. 화면 패널의 **🤖 로봇이 받는 정보**에서 블루 로봇의 실시간 관측과 고른 행동을 볼 수 있습니다.

| 축 | 공이 다가올 때 받는 정보 | 상대 차례일 때 받는 정보 | 행동 |
|---|---|---|---|
| x 앞뒤 | 공이 라켓 위치까지 오는 남은 시간(스윙 직전을 잘게), 라켓이 네트에서 떨어진 거리, 앞뒤 속도, 공 바운드 여부 | 라켓 위치, 속도, 공이 내 쪽인지 | 목표 속도 5단계 (◀◀ 뒤 ~ ▶▶ 앞) |
| y 위아래 | 남은 시간, 공이 라켓보다 얼마나 높은지, 공이 올라가는지 내려가는지, 바운드 여부, 위아래 속도 | 라켓 높이, 속도, 공 위치 | 목표 속도 5단계 (▼▼ ~ ▲▲) |
| z 좌우 | 남은 시간, 예상 도착 오차(지금 속도 그대로 오면 라켓 기준 좌우 어디로 오나), 좌우 속도 | 라켓 좌우 위치, 속도, 공 위치 | 목표 속도 5단계 (◀◀ 왼쪽 ~ ▶▶ 오른쪽) |
| 손목 위아래 | 남은 시간, 지금 라켓 면 각도, 위아래 속도, 바운드 여부 | 라켓 면 각도, 공 위치 | 목표 각도 5단계 (많이 닫기 ~ 많이 열기) |
| 손목 좌우 | 남은 시간, 지금 라켓 면 각도, 좌우 속도, 예상 도착 오차 | 라켓 면 각도, 공 위치 | 목표 각도 5단계 (왼쪽으로 ~ 오른쪽으로) |

팔에는 관성이 있습니다(축마다 가속도 한계). 그래서 미리 출발하고 제때 멈추는 것까지 학습해야 합니다. 손목도 한 스텝에 돌 수 있는 각도가 정해져 있습니다.
탁구대는 단단한 물체라서, 라켓은 위에서 오면 상판 위에서 멈추고 옆에서 오면 옆면에 막힙니다.

라켓은 **실제 크기**입니다. 면 15.0×15.8cm 타원, 두께 약 1.6cm, 손잡이 10cm를 게임 비율(탁구대 2.74m = 14, 1m ≈ 5.1)로 환산했습니다. 공도 실제 크기(지름 4cm)입니다.

공은 **라켓 면에 실제로 닿아야** 맞습니다. 한 스텝 동안 공이 지나간 경로로 판정하기 때문에, 빠른 공도 라켓을 건너뛰지 않습니다.
공이 내 코트에 튀기 전에 라켓에 닿으면(오브스트럭션) 통과하지 않고 라켓에 막혀 튕기며, 그 판은 무득점입니다.

**타구**는 공이 라켓에 닿는 순간의 **팔 스윙**으로 정해집니다(단순화한 라켓 모델).
- 앞으로 미는 속도 → 착지 깊이: 너무 약하면 네트, 너무 세면 아웃
- 위로 올리는 속도 + 손목 위아래(면 열기) → 네트 위 여유 높이: 닫거나 아래로 치면 네트, 너무 열면 길어져 아웃
- 좌우 속도 + 손목 좌우 + 라켓 중심에서 벗어난 정도 → 좌우 방향: 너무 크면 사이드 아웃

랠리가 이어지도록 공이 너무 날카롭지 않게 했습니다. 좌우 방향에 대한 영향은 예전의 절반이고, 공의 최고 수평 속도는 1.0입니다.

## 보상

| 사건 | 보상 |
|---|---|
| 공을 **받으면** (라켓에 닿음) | +45 |
| 공을 **넘기면** (네트를 넘어 상대 코트에 들어감) | +75 |
| **랠리 보너스**: 한 판에서 공이 상대 코트에 들어갈 때마다(k번째) | +30 × 1.5^(k−1), 최대 +150 (넘기기 보상에 더해짐) |
| 포인트를 **이기면** | +80 |
| 포인트를 지면 | −80 |
| 아무도 공을 건드리지 못한 판, 튀기 전에 라켓에 맞은 판(오브스트럭션) | 무득점 (점수·승패 보상 없음), 서브 차례가 상대에게 넘어감 |
| 무득점 판에서 서브를 못 건드린 쪽 | 학습 벌점 −20 (점수와는 무관) |

"지면" 보상이 없으면 학습 중간에 정책이 "모든 공을 네트에 꽂는" 쪽으로 자주 무너집니다.
받기·넘기기 보상을 승패보다 너무 작게 하면(예: 이기면 100 · 지면 −100 · 넘기면 5 · 받으면 1) 승패의 무작위성에 묻혀서, 시드 4개 중 2개에서 로봇이 공 받기를 아예 배우지 못했습니다. 그래서 받기·넘기기 보상을 크게 두었고, 랠리를 늘리려고 승패 ±80 · 받기 45 · 넘기기 75로 조정했습니다.
랠리 보너스는 길게 주고받을수록 커지게 해서 랠리를 이어 가도록 유도합니다. 처음 시도한 +10(최대 60)은 너무 작아서, 시드 3개 중 2개에서 로봇이 공을 아예 건드리지 않는 쪽으로 학습이 무너졌습니다. 그래서 +30(최대 150)으로 정했습니다.

타구 후에도 팔은 멈추지 않고 다음 공을 준비하며 계속 움직입니다. 다만 공을 친 스윙의 (상태, 행동)은 따로 보관해 두었다가, 공이 상대 코트에 떨어지면 "넘기면" 보상을 그 스윙에 줍니다. 네트나 아웃으로 판이 끝나면 승패 보상도 그 스윙이 받습니다.

## 강화학습 구조

축별 표 형식 **Q-러닝(TD(0))** 입니다. x·y·z와 손목 2축이 각자 Q-테이블을 가지고, 같은 보상을 받아 따로 학습합니다.

```
Q(s,a) ← Q(s,a) + α · [ r + γ · max_a' Q(s',a') − Q(s,a) ]      (종료 상태면 γ항 없음)
α = 0.10,  γ = 0.95
ε-greedy 탐험: ε 1.0(완전 무작위) → 포인트마다 ×0.998 → 하한 0.05
```

- **에피소드**는 한 포인트(서브부터 득점까지)입니다. 서브는 학습하지 않고 정해진 동작입니다.
- **셀프플레이**: 블루와 레드가 Q-테이블을 공유해서 경험이 두 배로 쌓입니다. 좌표는 모두 자기 기준(앞 = 상대 쪽, 오른쪽 = +)으로 바꿔서, 양쪽에서 같은 상황은 같은 상태가 됩니다.

## 학습이 되는지 확인하는 방법

학습된 로봇과 **학습 안 된 로봇(빈 Q-테이블)** 을 붙여서 비교합니다. 두 로봇은 물리, 규칙, 코드가 모두 같고 **Q-테이블 내용만** 다릅니다.
미학습 로봇은 팔을 무작위로 휘둘러서 공을 거의 받지 못합니다(받기 약 5%).

| 방법 | 어디서 | 무엇을 보나 |
|---|---|---|
| 📈 학습 곡선 | 화면 오른쪽 **학습 검증** 패널 | 체크포인트마다 학습 로봇 복사본(학습 정지, ε=0)이 미학습 로봇과 100점을 겨룹니다. 그 승률을 학습량에 따라 그린 곡선입니다 |
| ⚔️ 학습 로봇 vs 미학습 로봇 | 패널 상단 모드 버튼 | 🔵 블루는 지금까지 학습한 로봇, 🔴 레드는 미학습 로봇으로 실제 경기를 보여 줍니다 |
| 🔬 지금 검증 | 패널 버튼 | 200점 대결과 **대조군**(미학습 vs 미학습 ≈ 50%)을 받기·넘기기 성공률과 함께 보여 주고, z-점수로 우연인지 판정합니다 |
| `node verify-learning.js` | 터미널 (Node.js) | 같은 코드를 브라우저 없이 실행해 학습 곡선과 최종 판정을 출력합니다(학습 확인 시 종료 코드 0) |

체크포인트 평가와 **🔬 지금 검증**은 화면이 멈추지 않도록 여러 프레임에 나눠 계산합니다. 한 번 평가할 때 무득점 판까지 포함한 판 수에 상한이 있어서, 둘 다 공을 거의 못 받는 학습 초반에는 결정된 점수가 적게 나옵니다(표에 점수 수 표시).

화면 아래 **그림자 켬/끔** 버튼으로 그림자를 끌 수 있습니다(느린 컴퓨터에서 빨라짐, 설정은 브라우저에 기억).

빠르게 확인하는 순서: **⚡ 빠른 학습 +1000판**을 3~5번 → 곡선이 50%에서 95% 이상으로 오르는지 확인 → **⚔️ 학습 로봇 vs 미학습 로봇** 모드에서 **시작**.

## 화면 구성 (왼쪽 위 탭)

| 탭 | 내용 |
|---|---|
| **🧬 진화** | 자연 선택 진화만 진행합니다. 3D 화면에서는 현재 세대 최고 개체(🔵)가 볼 머신 테스트를 합니다 |
| **🎓 강화** | 강화학습(Q-러닝) 화면입니다. 학습 곡선, 학습 로봇 vs 미학습 로봇 대결, 로봇이 받는 정보를 볼 수 있습니다 |
| **⚖️ 비교** | 같은 경험(친 판 수)을 준 강화학습 로봇과 진화 로봇을 나란히 비교합니다. 3D로 둘의 대결도 볼 수 있습니다 |

탭 아래 **숨기기**(단축키 H)를 누르면 버튼과 패널을 모두 숨깁니다. 진화와 비교 학습은 다른 탭으로 옮겨도 계속 진행됩니다.

## 🧬 자연 선택 진화

뇌는 작은 신경망입니다. 관측 16개를 은닉층 12개를 거쳐 출력 5개로 바꾸며, 출력은 팔 3축의 목표 속도와 손목 2축의 목표 각도입니다. 경기 중에는 학습하지 않고, 세대가 바뀌면서 진화합니다. 각 세대의 평가는 **🎾 볼 머신 테스트**로 합니다.

**볼 머신 테스트**
- 상대 쪽 볼 머신이 로봇 코트의 무작위 지점으로 공을 쏩니다. 로봇이 받아서 상대 코트에 넘기면 바로 다음 공이 날아옵니다.
- 연속으로 성공할수록 공이 빨라지고(+8%씩, ±10% 무작위), 날아오는 범위도 가운데에서 코트 전체로 넓어집니다.
- 놓치거나 네트·아웃이 나면 테스트가 끝납니다.
- 점수는 성공한 공마다 그 공의 속도 배율(1, 1.08, 1.16…)을 더한 값입니다. 연속 개수와 공 속도를 함께 반영합니다.

**진화 과정**
1. 한 세대는 24개체입니다. 각 개체는 볼 머신 테스트를 12번 치르고, 그 평균 점수로 평가받습니다.
2. 점수 상위 **10% / 25% / 50%**만 살아남습니다(진화 탭에서 선택).
3. 나머지 자리는 생존자를 **돌연변이**시킨 자식으로 채웁니다. 각 가중치가 15% 확률로 무작위 값만큼 바뀝니다. 이 과정을 반복합니다.

처음에는 모든 개체가 0점이라 누가 나은지 고를 수 없습니다. 그래서 **선택할 때만** 가산점을 더합니다. 마지막 공에 닿았으면 +0.5, 닿지 못했으면 라켓이 공에 가까웠던 만큼 최대 +0.5입니다. 화면에 표시되는 점수에는 이 가산점이 들어가지 않습니다.

시드 3개로 100세대를 돌려 봤습니다. 최고 개체의 평균 연속 받기는 2.5개, 6.5개, 7~9개였고, 최고 기록은 11~16개였습니다. 미학습 로봇은 0개입니다.

진화 탭에서 볼 수 있는 것:
- 세대별 최고·평균 점수 차트
- 최고 개체의 연속 받기(평균·최고)
- 최고 개체가 볼 머신 테스트를 하는 3D 화면(실패하면 점수를 남기고 다시 시작)

비교 탭의 차트 지표는 받기 성공률(기본)·승률·넘기기 성공률 중에서 고를 수 있습니다. 학습 초반에는 둘 다 공을 거의 못 받아 점수가 나는 판이 적습니다. 그래서 승률보다 받기 성공률이 실력을 더 잘 보여 줍니다. 시드 3개로 측정했을 때, 둘 다 경험 1만 판 무렵 받기 성공률이 대체로 86~100%였습니다. 다만 중간 과정은 시드마다 다릅니다.

## 파일 구성

- `ai-pingpong-rl.html`: 게임 전체입니다. `<script id="rl-core">`에는 물리, 규칙, 로봇팔 Q-러닝 코어가 들어 있고 DOM이나 Three.js를 쓰지 않습니다. 그 아래 스크립트는 3D 렌더링(로봇팔 모델 포함)과 UI입니다.
- `verify-learning.js`: HTML에서 `rl-core`를 그대로 꺼내 Node에서 학습과 검증을 실행합니다.
